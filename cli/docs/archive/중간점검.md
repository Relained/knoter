  Slide 1. 프로젝트 개요 및 기획 배경 (Why)
  
  개인 지식 관리 도구의 한계 극복 및 로컬 중심의 AI 통합
  
      Problem (기존의 문제점):
  
          노트는 지속적으로 축적되지만, 의미 기반 검색의 부재로 인해 정보의 실질적인 활용도가 저하됨.
  
      Solution & Differentiator (해결책 및 차별점):
  
          CLI & MCP 기반 개방형 구조: 외부 에이전트와 매끄럽게 연동되어 높은 확장성과 유연성을 보장함.
  
  Slide 2. 핵심 아키텍처 및 설계 결정 (How)
  
      Bun 사용함
  
      Storage 아키텍처 (SQLite + zvec):
  
          벡터는 ANN(근사 최근접 이웃) 검색에, 메타데이터는 트랜잭션 및 FTS5 검색에 배분하여 단일 스토리지의 한계 극복.
  
      하이브리드 검색 엔진:
  
          BM25(키워드) + 의미 벡터(Semantic)의 선형 퓨전. 서로 놓치기 쉬운 쿼리 타입을 상호 보완하는 Strong-signal shortcut 역할.
  
      최적화된 인덱싱 및 임베딩 파이프라인:
  
          SHA-256 증분 인덱싱: 파일 해시 변경 감지를 통해 비용과 시간이 가장 크게 소모되는 불필요한 재임베딩 제거.
  
          스마트 청커 (Smart Chunker): CJK(한중일) 텍스트 비율 감지 및 자동 축소, Break-point 스코어링 도입으로 문맥 훼손 방지.
  
      임베딩 서버:
  
          TEI 도커 컨테이너 동적 로딩 (Lazy-start) 및 OpenAI 호환 단일 프로토콜 사용.
          
          테스트 임베딩 모델: 한국어 환경 최적화를 위해 HuggingFace dragonkue 컬렉션의 한국어 임베딩 모델들을 참조하여 테스트 진행 중.
  
  Slide 3. 현재 개발 상황 및 구현 지표 (What)
  
  백엔드 파이프라인 전 구간 동작 완료
  
      핵심 커맨드 (총 9종):
  
          CRUD & 검색: add, get, search, remove(미구현)
  
          DB 관리: vault, tag, sync
  
          서비스 및 확장: schedule (스케줄러), mcp (외부 에이전트 개방), cluster (마일스톤/그래프 노드 관리)
  
      파이프라인 완성:
  
          add → chunker → embed → store → search → mcp에 이르는 일관된 데이터 흐름 구축 완료.
  
      현재 진행 중 (WIP):
  
          인덱스 측 Preprocessor 적용, HDBSCAN 업그레이드, 프론트엔드 연동 준비.
  
  Slide 4. 데이터 플로우 아키텍처 (Diagram)
  Plaintext
  
  [입력] File / Text
     ↓
  [전처리] Parser → Smart Chunker (CJK 최적화)
     ↓
  [임베딩] Embedder (TEI Docker / API)
     ↓
  [저장소] ── Metadata ──▶ [ SQLite (FTS5) ]
           └─ Vector Data ─▶ [ zvec (ANN) ]
     ↑
  [검색] Hybrid Search (BM25 + Semantic 선형 퓨전)
     ↑
  [인터페이스] CLI / MCP (에이전트) / Electron (프론트엔드)
  
  Slide 6. 프론트엔드 계획 및 사용자 경험 (Frontend UX)
  
  작업 효율을 극대화하는 UI 워크플로우
  
      기술 스택: Electron + React + Vite
  
      레이아웃 구성:
  
          사이드바 (파일 트리 뷰어 등 구조 탐색) + 메인 UI 창 (탭, 문서 편집기)
  
      핵심 UX 포인트:
  
          Command Palette: 마우스 이동을 최소화하고 Spotlight 스타일의 키보드 중심 빠른 워크플로우 통합.
  
          Floating 창: 메인 화면의 작업 흐름을 끊지 않고 Todo, 그래프 뷰 등의 부가 기능 제공.
  
  Slide 7. 향후 발전 방향 및 검증 계획 (Future & Evaluation)
  
      배포 접근성 개선 (UX/DevOps):
  
          이슈: 일반 사용자 기준에서 Docker 설치 및 등록이 진입 장벽으로 작용할 수 있음.
  
          해결 방안: 프론트엔드 레벨에서의 자동화 스크립트 지원 또는 실행 바이너리에 임베딩 서버 직접 포함 검토.
  
      검증 지표(Metrics) 도입 예정:
  
          검색 품질: Golden Set 구축 및 MRR / Recall@K 측정.
  
          성능: 인덱싱 처리량 및 임베딩 지연 시간(로컬 vs API) 벤치마킹.
  
      기능 고도화 계획 (Milestone):
  
          AI 자동화: 클러스터링을 활용한 마일스톤 문서 자동 생성(LLM Wiki 스타일 등 다양한 템플릿 지원).
  
          데이터 분류: 개인정보 및 시의성 데이터의 자동 분류.
